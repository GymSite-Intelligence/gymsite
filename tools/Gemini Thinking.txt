## Como Gemini Thinking ajuda o GymSite Intelligence

### O que muda na prática

Hoje todos os agentes rodam com `gemini-2.5-flash` em modo dinâmico — o modelo decide sozinho quanto pensar. Com o que a documentação mostra, você pode **calibrar o esforço de raciocínio por agente** com base na complexidade real da tarefa.

A regra da documentação é clara: tarefas simples de recuperação de dados não precisam de thinking pesado. Tarefas de síntese, raciocínio e decisão estratégica se beneficiam muito.

---

### Mapeamento por agente — configuração ideal

| Agente | Tarefa | Complexidade | Configuração Recomendada |
|---|---|---|---|
| **A0** ContextBuilder | Chama Deep Research, formata JSON | Baixa — é só estruturar o output | `thinking_budget=0` — desligar thinking |
| **A1** GeoScout | Geocodifica, chama Maps API, score heurístico | Baixa — mecânico | `thinking_budget=0` |
| **A2** DemoAnalyst | Interpreta dados IBGE, calcula percentuais | Baixa-média | `thinking_budget=512` |
| **A3** CompetitorIntel | Sintetiza reviews, identifica dores, decide gaps | **Alta** — julgamento estratégico | `thinking_budget=8192` ou Gemini 3 |
| **A4** FinancialEstimator | Calcula 3 cenários, interpreta viabilidade | Média — tem fórmulas mas requer julgamento | `thinking_budget=2048` |
| **A5** ContactHunter | Gera script de abordagem personalizado | Média — criativo mas estruturado | `thinking_budget=1024` |
| **A6** ReportConsolidator | Integra tudo, escreve relatório executivo | **Alta** — síntese complexa, decisão de bairros alternativos | `thinking_budget=8192` |

**Resultado prático:** A0 e A1 ficam ~3x mais rápidos e ~60% mais baratos. A3 e A6 ganham qualidade real nas decisões estratégicas.

---

### Oportunidade de upgrade — Gemini 3 Flash

A documentação revela `gemini-3-flash-preview` com `thinkingLevel` em vez de `thinkingBudget`. Para o **A3 CompetitorIntel** e **A6 ReportConsolidator**, o Gemini 3 com `thinkingLevel="high"` pode entregar raciocínio significativamente superior ao 2.5-flash no mesmo custo — especialmente na análise de padrões em múltiplos reviews e na síntese do relatório final.

---

### Implementação no código

No ADK, o `thinking_config` vai no parâmetro `generate_content_config` do agente:

```python
# agents/a3_competitor_intel.py — agente estratégico, thinking alto
from google.adk.agents import Agent
from google.genai import types

a3_competitor_intel = Agent(
    name="a3_competitor_intel",
    model="gemini-2.5-flash",
    generate_content_config=types.GenerateContentConfig(
        thinking_config=types.ThinkingConfig(
            thinking_budget=8192  # raciocínio profundo para análise competitiva
        )
    ),
    ...
)

# agents/a1_geoscout.py — tarefa mecânica, sem thinking
a1_geoscout = Agent(
    name="a1_geoscout",
    model="gemini-2.5-flash",
    generate_content_config=types.GenerateContentConfig(
        thinking_config=types.ThinkingConfig(
            thinking_budget=0  # desligar — só chama API e formata JSON
        )
    ),
    ...
)
```

### Outra aplicação direta — Thought Summaries no debug

Quando o pipeline errar ou produzir output estranho, você pode ligar `include_thoughts=True` temporariamente em qualquer agente para ver o raciocínio interno:

```python
# Debug mode — ver por que o A3 chegou numa conclusão estranha
thinking_config=types.ThinkingConfig(
    thinking_budget=8192,
    include_thoughts=True  # expor o raciocínio no output
)
```

O log vai mostrar exatamente onde o agente tomou uma decisão errada — muito mais útil que tentar adivinhar pelo output final.

Gemini Thinking não é só uma feature — é uma **alavanca de custo e qualidade**.
